# Proofly — Level 2 Deployment Guide (Midnight Preprod)

This guide describes the **one-time, operator-only** deployment of the deployed
Proofly contract to the **Midnight Preprod testnet**. It is separate from the
application model: the Netlify static-hosting architecture serves a **static
frontend** that talks to the deployed contract via Lace. The deployer process
below runs on a **local
machine**, is never part of the Netlify build, and uses **testnet resources
only — no real money.**

> Status: **replaced by Level 3.** This guide describes how the Level 2
> deployment was prepared and executed. The executed Level 2 record lives in
> `docs/evidence/DEPLOYMENT.md`; the Level 3 contract (per-application replay
> protection) was deployed to Preprod with this exact same procedure and its own
> record in the Level 3 section of the same evidence file. The steps below remain
> the canonical operator procedure for any future redeployment.

---

## 1. Architecture

```
LOCAL MACHINE (operator, one-time)
   local proof server (Docker, port 6300)          ──npm run proof-server:start
        │
   wallet-sdk ↔ Midnight Preprod (public indexer/RPC)
        │
   scripts/deploy-proofly.ts  →  deployContract
        │
        ▼
   Proofly contract deployed on Preprod
        │
        ▼
   docs/evidence/DEPLOYMENT.md (non-secret)

DEPLOYED APP (unchanged model)
   Netlify static frontend  →  Lace  →  Proofly contract on Preprod
```

The deployer script is **not** part of the deployed application and is **not**
exposed to Netlify, GitHub Actions, or any CI.

## 2. Prerequisites

| Requirement | Version / Notes |
|---|---|
| **Node.js** | 22.x (`engines` in root package.json) |
| **Compact toolchain** | pinned **0.31.1** (`compact update 0.31.1`) |
| **Docker** | running engine — the **proof server is REQUIRED** for the wallet-sdk proving path |
| **Proof server** | `midnightntwrk/proof-server:8.1.0`, local-only, port 6300 |
| **Official toolchain/dev tooling** | same as Level 1/2 builds |

### Why the proof server is required

The `wallet-sdk` 1.2.0 deployment path (and the reference Flash Loan /
ShadowPass deployments this script is modelled on) proves every transaction
locally through a proof server. The wallet configuration points
`provingServerUrl` at `http://127.0.0.1:6300`. Midnight's official
documentation and the reference repositories all run the proof server as a
Docker container for Preprod deployment — you do **not** need a local node or
indexer, only the proof server. The Netlify app does **not** depend on it
(Lace provides proving for the wallet user).

Start it locally:

```bash
npm run proof-server:start     # docker compose up -d   (image proof-server:8.1.0, port 6300)
npm run proof-server:ps        # verify it is up
```

It downloads the public SRS parameters on first boot. Do not expose port 6300
publicly; `compose.yml` is local-use only.

## 3. Preflight validation (no network, no transactions)

```bash
npm run deploy:proofly:validate
```

This runs `scripts/deploy-proofly.ts --validate`, which checks — without
creating a wallet, syncing, or submitting anything:

- `PROOFLY_DEPLOYER_SEED` is set and is 64 hex chars
- network guard is `preprod`
- compiled contract artifacts exist (`contract/index.js`, `zkir/`, `keys/`,
  `compiler/contract-info.json`) — otherwise it tells you to run `npm run compile`
- reports compiled compiler/runtime versions
- probes whether the local proof server is responding (informational;
  required before a real deploy)

## 4. Dedicated deployer wallet

Create a **dedicated deployer seed** — do not reuse any personal wallet:

```bash
openssl rand -hex 32
```

Keep it safe. It is the ONLY thing that controls the deployment wallet.
Because the wallet-sdk derives all child wallets (shielded / unshielded / dust)
from one 32-byte HD seed, a single seed is sufficient.

### Fund it with test resources (official process only)

On Preprod, fees are paid in **tDUST**, which is generated by holding (and
delegating) **tNIGHT**. Funding uses the official Midnight testnet / faucet
process — the deployment script does **not** mint, proxy, or fake funds. It
only verifies that tNIGHT is present and, if it is, runs the standard DUST
registration flow.

1. Note the deployer public address printed by the first sync (or derive it
   with a wallet-sdk CLI). 
2. Request tNIGHT through the official Midnight Preprod faucet for that
   address.
3. Wait for funds, then re-run. First run will also report whether DUST is
   ready; no funding shortcut exists.

## 5. Configure the environment

Copy the template and set your seed **locally only**:

```bash
cp .env.example .env          # .env is gitignored — NEVER commit it
# edit .env:
#   PROOFLY_DEPLOYER_SEED=<64-hex>
```

or export it in your shell without any file:

```bash
export PROOFLY_DEPLOYER_SEED="<64-hex>"
```

The script reads the seed **only** from the `PROOFLY_DEPLOYER_SEED` environment
variable (a `.env` / `.env.local` loader is provided for convenience; both
paths are gitignored and never committed). Additional optional variables:

| Variable | Meaning |
|---|---|
| `PROOFLY_NETWORK_ID` | must stay `preprod` (safety guard) |
| `PROOFLY_INDEXER_URL` / `PROOFLY_INDEXER_WS_URL` | public Preprod indexer overrides |
| `PROOFLY_NODE_URL` | public Preprod RPC override |
| `PROOFLY_PROOF_SERVER_URL` | default `http://127.0.0.1:6300` |
| `PROOFLY_PRIVATE_STATE_PASSWORD` | password for the deployer's local private-state store (LevelDB). Defaults to a local placeholder; set a strong value recommended by Midnight docs |

## 6. Exact deployment command

```bash
npm run compile                 # ensure compiled artifacts exist
npm test                        # all 47 tests green
npm run build                   # root TS check
npm run build:frontend          # static frontend build
npm run proof-server:start      # start the local proof server
npm run deploy:proofly:validate # preflight (optional but recommended)
PROOFLY_DEPLOYER_SEED="<64-hex>" npm run deploy:proofly
```

The script performs these steps in order:

1. fails immediately if `PROOFLY_DEPLOYER_SEED` is absent/malformed;
2. refuses anything other than `preprod`;
3. creates the deployer HD wallet (restore-from-saved-state when present);
4. syncs with Preprod;
5. persists wallet state under `.midnight-wallet-state/` (gitignored);
6. verifies tNIGHT is present (no fake funding) and registers UTXOs for DUST;
7. verifies DUST is available;
8. re-asserts the network is `preprod`;
9. requires typing `DEPLOY` to confirm;
10. deploys the Proofly contract and waits for the transaction to confirm;
11. extracts contract address, transaction ID, block height, block hash;
12. writes **non-secret** evidence to `docs/evidence/DEPLOYMENT.md`.

## 7. Security warnings

- **NEVER** hardcode, print, commit, or paste the seed. It is read from
  `PROOFLY_DEPLOYER_SEED` and never written to disk by the script.
- **NEVER** commit `.env`, `.env.local`, `.env.preprod`, or
  `.midnight-wallet-state/` — all are gitignored.
- The deployer wallet state (`shielded/unshielded/dust.json`) is derived from
  the seed; treat it as secret and keep it out of Git.
- The script writes **only** non-secret evidence (`docs/evidence/DEPLOYMENT.md`):
  network, contract address, tx ID, block height, block hash, timestamp,
  compiler/runtime versions, public deployer address. It can be committed.
- LevelDB private-state files created by `levelPrivateStateProvider` live
  under `node_modules/` (gitignored) and are protected by the private-state
  password.

## 8. After deployment: wiring the address into the app

1. Copy the contract address shown by the script (also in
   `docs/evidence/DEPLOYMENT.md`).
2. In `frontend/.env` set:
   ```
   VITE_CONTRACT_ADDRESS=<hex address>
   ```
   (`frontend/src/config.ts` reads `VITE_CONTRACT_ADDRESS` — it is empty now;
   do not paste a real address into source.)
3. Rebuild and publish the static app:
   ```bash
   npm run build:frontend
   # publish frontend/dist to Netlify (static hosting only)
   ```

## 9. Verifying the deployment

- The script prints `✅ Contract deployed successfully` and waits for the
  deploy transaction to confirm before returning.
- Verify in the Midnight block explorer that the Proofly contract exists at the
  reported address on **preprod**.
- Optional: connect Lace on Preprod and run the Live Preprod panel; with
  `VITE_CONTRACT_ADDRESS` set, the ProofCounter should read `proofCount = 0`
  on-chain.

## 10. Explicit exclusions

- Deployments **are** executed from this repository; the deployer script is
  still operator-only and never run by Netlify, GitHub Actions, or any CI.
- No deployer seed exists in the repository, tests, or CI — it is supplied at
  runtime via `PROOFLY_DEPLOYER_SEED`.
- Level 3 replay protection (nullifiers) **is** implemented and deployed on the
  same contract address; see `docs/evidence/DEPLOYMENT.md` and
  `docs/LEVEL3-ARCHITECTURE.md`. What remains out of scope is an issuer
  authority, applicant-id registries, Merkle allowlists, thresholds stored
  on-chain, and revocation — none are part of the current contract design.
- The privacy circuit (`contracts/proofly.compact`) keeps income as a witness;
  the circuit arguments are now `requiredMonthlyIncome` **and** `applicationId`
  (Level 3 claim scoping), not a single argument.
